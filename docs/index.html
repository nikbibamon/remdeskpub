02

Add RemDesk

For an individual account, open Customize → Connectors → + Add → Add custom connector. If RemDesk already exists, open that connection.

Name
Tvijo Remote Desktop Commander
MCP server URL
https://mcp.tvijo.com/mcp
  1. Enter the name and URL without extra spaces.
  2. Confirm authentication is OAuth. If asked how to register the client, choose Register automatically: the server advertises dynamic registration.
  3. Select Sign in now. With Sign in when needed, a tool request starts sign-in.
Team / Enterprise setup

The organization owner adds it through Organization settings → Connectors → Add → Custom → Web. Members then use Customize → Connectors → Connect. Labels can vary between interface versions.

03

Approve access

Claude opens authorization. Before entering anything, verify the domain is https://mcp.tvijo.com. Read the displayed permissions.

Current implementation: source documents consent using a host operator approval token, not email sign-in. This screen has not yet been exercised through Claude. If it differs, stop and record a sanitized error.

  1. If you own the host and see the approval field, obtain the existing token from its configured source on your host. The RemDesk startup option -oauth-admin-token-file selects that file. Do not replace the key.
  2. Enter it only in the verified HTTPS consent form if its permissions fit your test. Never send it to Claude, GitHub, support or a reviewer.
  3. Select Approve if shown and wait to return to Claude. Do not copy the callback URL: it may contain a one-time code.
  4. If you lack the token or host access, ask the owner for suitable access. MIT does not issue a hosted account or server.

Success: Claude shows the connection as available, and a tool request does not send you back to sign-in.

04

Test the tools

Start a new conversation and enable RemDesk under + → Connectors. Begin with safe read-only checks.

Prompt 1 · status
Check RemDesk status. Do not change files, run commands or submit tasks. Show the actual tool response.
Prompt 2 · commands
List commands approved by RemDesk and their argument restrictions. Do not execute anything.
Prompt 3 · project
Read README.md and app.py in my authorized review-fixture project and explain the greeting function. If you do not know the path, ask me. Make no changes.

Confirm Claude actually called a tool. The explanation should match app.py. On denial, verify the authorized path instead of granting the whole host.

Keep the date, tool names and result. Exclude keys, tokens and callback URLs containing codes from screenshots.

05

Reconnect safely

  1. In Customize → Connectors, select RemDesk and use the available disconnect action or Remove in its menu.
  2. In a new conversation, confirm the removed connection no longer provides tools. A conversation toggle is not connection removal.
  3. Add the same URL again, or use Connect if it remains configured. Repeat sign-in and the status request.

This checks client disconnection and reconnection. Server revocation, expiry and refresh need separate tests on isolated access. Do not stop production or activate a global kill switch for this test.

06

Prepare reviewer access

A reviewer needs separate access to synthetic data. The production operator token is not a reviewer account.

  1. Have the maintainer prepare isolated access and a fixture on the submitted endpoint. A different staging test does not prove this connection works.
  2. Verify the reviewer can sign in without your account or operator token.
  3. Follow the reviewer guide and cases for every exposed tool. Write only a new fixture file, execute only approved harmless commands, and set a separate allowance for paid tasks.
  4. Provide access details only in secure portal fields.

Still unverified: separate reviewer sign-in and a complete Claude OAuth journey. If access only works through a shared operator token, the service first needs a suitable review-access arrangement.

Troubleshooting

HTTP 401 before sign-in

Expected: the server should reject anonymous requests. If 401 persists after sign-in, start a fresh OAuth session and save a sanitized error.

invalid_redirect_uri or broken callback

The maintainer must check registration and Claude’s allowed callback URI. Do not edit it manually or allow arbitrary URLs. Do not forward the one-time code.

invalid_grant or invalid_client

Start a fresh sign-in from Claude: an old one-time code may have expired or been consumed. Repeated errors require server logs. Never send tokens or the full callback URL.

Connected, but no tools

Check + → Connectors, account permissions and current tools/list. Reachable discovery does not prove tool access.

What was tested automatically?

The dated report contains public checks and a separate 9-test isolated source suite for consent, PKCE, token issuance and validation. Refresh-token exchange/rotation was not tested. The diagnostic does not register clients or obtain tokens; it cannot verify your Claude session.
