01

Подготовьте аккаунт

Используйте аккаунт и организацию Claude, которым должна принадлежать заявка. Нужен подходящий платный план; в Team/Enterprise может потребоваться роль владельца.

  • Издатель: Tvijo. Оператор: Nik Bibamon, физическое лицо. Контакт: admin@tvijo.com. Страна не указана — впишите фактическую страну, если форма её требует.
  • Для тестов используйте отдельную рабочую область с синтетическими данными, не production.

Не проверяйте и не отправляйте заявку с общим ключом владельца. Ограниченный production-пилот проверен для одной выбранной учётной записи и только mcp:read. Реальное согласие Claude и вызовы инструментов остаются NOT_RUN; доступ отдельного внешнего рецензента ожидает настройки.

02

Добавьте RemDesk

В личном аккаунте откройте Customize → Connectors → + Add → Add custom connector. Если RemDesk уже подключён, откройте существующую запись.

Название
Tvijo RemDesk
MCP server URL
https://mcp.tvijo.com/mcp

Если в аккаунте уже есть подключение «Tvijo Remote Desktop Commander», выберите его; не создавайте дубликат. Проверенный production-пилот ограничен одной выбранной учётной записью и областью mcp:read. Реальная сессия Claude остаётся NOT_RUN.

Настройка Team / Enterprise

Владелец организации добавляет сервер через Organization settings → Connectors → Add → Custom → Web. Участник затем открывает Customize → Connectors → Connect. Названия пунктов могут отличаться.

05

Повторите подключение

  1. В Customize → Connectors выберите RemDesk и Remove в меню подключения (при необходимости откройте меню с тремя точками).
  2. В новом чате проверьте, что удалённое подключение больше не даёт инструменты. Переключатель одного чата не равен удалению подключения.
  3. Добавьте тот же URL снова либо выберите Connect, если запись осталась. Повторите вход с уже выбранной учётной записью и ограниченную проверку чтения/списка; зафиксируйте результат, так как реальное переподключение Claude ещё NOT_RUN.

Это проверяет отключение и повторное подключение клиента. Отзыв, истечение и обновление токенов на сервере проверяются отдельно на изолированном доступе. Не останавливайте рабочий сервер и не включайте общий аварийный выключатель для этого теста.

06

Подготовьте аккаунт проверяющего

Для заявки на коннектор нужны тестовые данные полностью настроенного аккаунта и инструкция для проверки submitted connector. Проверяющий должен войти под своей учётной записью на том же URL, что указан в заявке.

  1. Доступ отдельного внешнего рецензента пока ожидает настройки. Подготовьте отдельную синтетическую рабочую область на https://mcp.tvijo.com/mcp; не публикуйте учётные данные.
  2. Проверьте вход без аккаунта, пароля, сессии или операторского ключа владельца.
  3. Зафиксируйте точный список инструментов, показанных проверяющему, и успешный допустимый ввод для каждого инструмента в заявке. Для изменения данных используйте отдельную тестовую область; платные задачи требуют явного лимита расходов.
  4. Передавайте данные входа только в закрытых полях портала. Не кладите их в GitHub, публичные материалы или чат.

Не готово к Directory review: доступ отдельного внешнего рецензента и проверки каждого инструмента ожидают выполнения. Реальное подключение Claude и вызовы инструментов остаются NOT_RUN.

Лимит и дубликаты: организация может подать не более 10 заявок за любые 24 часа; сохранённые черновики и отозванные заявки учитываются. Для пары «репозиторий + папка» допускается одна заявка; первая организация, подавшая её, закрепляет эту карточку. Связанные коннектор и плагин подавайте из одной организации.

Не отправляйте заявку, пока открыт хотя бы один блокер. После отправки следите за замечаниями портала. Эти отметки сохраняются только локально и не отправляют заявку.

Если что-то не работает

HTTP 401 до входа

Это ожидаемо: сервер должен отклонять анонимные запросы. Если 401 повторяется после входа, начните новый OAuth-сеанс и сохраните безопасный текст ошибки.

invalid_redirect_uri или возврат не работает

Сопровождающему нужно проверить регистрацию клиента и разрешённый адрес возврата Claude. Не меняйте его вручную и не разрешайте любые URL. Не пересылайте одноразовый код.

invalid_grant или invalid_client

Начните новый вход из Claude: старый одноразовый код мог истечь или уже использоваться. Повторная ошибка требует проверки серверных журналов. Не отправляйте токены или полный URL с кодом.

Подключено, но инструментов нет

Проверьте + → Connectors, разрешения аккаунта и актуальный tools/list. Доступность discovery ещё не означает доступ к инструментам.
