01

Подготовьте аккаунт

Используйте аккаунт и организацию Claude, которым должна принадлежать карточка. Для подачи нужен подходящий платный план; в Team/Enterprise может потребоваться роль владельца.

  • Издатель: Tvijo. Оператор: Nik Bibamon, физическое лицо. Контакт: admin@tvijo.com. Страна пока не указана — впишите свою фактическую страну, если форма её требует.
  • Для собственного теста нужен доступ к серверу RemDesk и разрешённому проекту. Владелец сервера должен разместить тестовые файлы в разрешённом каталоге.

Что регистрируем: RemDesk — один коннектор с URL ниже. DSHREM (com.tvijo/dshrem) — другой продукт. RootRemDesk и оплата здесь не включаются. Arcade не требуется.

02

Добавьте RemDesk

В личном аккаунте откройте Customize → Connectors → + Add → Add custom connector. Если RemDesk уже есть, откройте существующее подключение.

Название
Tvijo Remote Desktop Commander
MCP server URL
https://mcp.tvijo.com/mcp
  1. Укажите название и URL без пробелов.
  2. Проверьте способ входа: OAuth. Если спрашивается способ регистрации клиента, выберите Register automatically: сервер объявляет динамическую регистрацию.
  3. Выберите Sign in now. При выборе Sign in when needed вход начнётся при запросе инструмента.
Для Team / Enterprise

Владелец организации добавляет сервер через Organization settings → Connectors → Add → Custom → Web. Затем участник открывает Customize → Connectors → Connect. Названия пунктов могут различаться в разных версиях интерфейса.

03

Подтвердите доступ

Claude откроет страницу авторизации. Перед вводом данных проверьте домен: https://mcp.tvijo.com. Прочитайте показанные разрешения.

Особенность текущей реализации: в исходниках описано подтверждение ключом владельца сервера, а не вход по email. Сам экран согласия через Claude ещё не проверен. Если он отличается, сохраните безопасный текст ошибки и остановитесь.

  1. Если вы владелец и видите поле подтверждения, получите существующий ключ из настроенного источника на своём сервере. Файл задаёт параметр запуска RemDesk -oauth-admin-token-file. Не заменяйте ключ новым.
  2. Введите ключ только в проверенную HTTPS-форму согласия, если права подходят вашему тесту. Не отправляйте его в Claude, GitHub, поддержку или проверяющему.
  3. Нажмите Approve, если эта кнопка показана, и дождитесь возврата в Claude. Не копируйте URL возврата: он может содержать одноразовый код.
  4. Если ключа или доступа к серверу нет, запросите подходящий доступ у владельца. MIT-лицензия не выдаёт аккаунт или сервер.

Успех: Claude показывает доступное подключение, а запрос инструмента не возвращает вас на вход.

04

Проверьте инструменты

Начните новый чат и включите RemDesk в + → Connectors. Сначала — только безопасные проверки чтения.

Запрос 1 · состояние
Проверь состояние RemDesk. Ничего не меняй, не запускай команды и не отправляй задачи. Покажи фактический ответ инструмента.
Запрос 2 · команды
Перечисли разрешённые команды RemDesk и ограничения аргументов. Ничего не выполняй.
Запрос 3 · проект
Прочитай README.md и app.py в моём разрешённом тестовом проекте review-fixture и объясни функцию greeting. Если путь неизвестен, спроси меня. Ничего не меняй.

Убедитесь, что Claude действительно вызвал инструмент. Объяснение проекта должно соответствовать app.py. При отказе уточните разрешённый путь, а не расширяйте доступ на весь сервер.

Сохраните дату, имена инструментов и результат. Уберите со скриншотов ключи, токены и адреса возврата с кодом.

05

Повторите подключение

  1. В Customize → Connectors выберите RemDesk и доступное действие отключения или Remove в меню подключения.
  2. В новом чате проверьте, что удалённое подключение больше не даёт инструменты. Переключатель одного чата не равен удалению подключения.
  3. Добавьте тот же URL снова либо выберите Connect, если запись осталась. Повторите вход и запрос состояния.

Это проверяет отключение и повторное подключение клиента. Отзыв, истечение и обновление токенов на сервере проверяются отдельно на изолированном доступе. Не останавливайте рабочий сервер и не включайте общий аварийный выключатель для этого теста.

06

Подготовьте проверяющего

Проверяющему нужен отдельный доступ к синтетическим данным. Ключ владельца рабочего сервера не является учётной записью проверяющего.

  1. Попросите сопровождающего подготовить изолированный доступ и тестовый проект на URL, указанном в заявке. Проверка другого стенда не доказывает работу этого подключения.
  2. Проверьте, что человек входит без вашего аккаунта и без получения ключа владельца.
  3. Пройдите инструкцию проверяющего и тесты для каждого доступного инструмента. Запись — только в новый тестовый файл, команды — только заранее разрешённые; платные задачи требуют отдельного лимита расходов.
  4. Передавайте данные доступа только в закрытых полях портала.

Пока не подтверждено: отдельный вход проверяющего и полный OAuth-сценарий Claude. Если всё работает только через общий ключ владельца, сначала нужно подготовить подходящую схему доступа на стороне сервиса.

09

Отправьте заявку

На последнем шаге портала проверьте сведения об оплате, обработке данных и все требуемые подтверждения правил. Отмечайте их сами, только когда они верны.

  • Вход через Claude и реальные запросы инструментов работают.
  • Каталог содержит корректные метаданные, каждый заявленный инструмент проверен.
  • Проверяющий получает изолированный доступ без ключа рабочего сервера.
  • Документация, политика, контакты, значок и GitHub-папка доступны публично.

После этого отправьте заявку на рассмотрение и следите за замечаниями в портале. Публичный репозиторий и успешная проверка пакета не означают одобрение Claude.

Галочки здесь — только ваш локальный список. Они не отправляют заявку и не подтверждают готовность сервера.

Если что-то не работает

HTTP 401 до входа

Это ожидаемо: сервер должен отклонять анонимные запросы. Если 401 повторяется после входа, начните новый OAuth-сеанс и сохраните безопасный текст ошибки.

invalid_redirect_uri или возврат не работает

Сопровождающему нужно проверить регистрацию клиента и разрешённый адрес возврата Claude. Не меняйте его вручную и не разрешайте любые URL. Не пересылайте одноразовый код.

invalid_grant или invalid_client

Начните новый вход из Claude: старый одноразовый код мог истечь или уже использоваться. Повторная ошибка требует проверки серверных журналов. Не отправляйте токены или полный URL с кодом.

Подключено, но инструментов нет

Проверьте + → Connectors, разрешения аккаунта и актуальный tools/list. Доступность discovery ещё не означает доступ к инструментам.

Что именно проверено автоматически?

Датированный отчёт содержит публичные проверки и отдельно 9 тестов изолированной копии кода. Они проверили согласие, PKCE, выдачу и проверку токена. Обмен/ротация refresh token не тестировались. Скрипт не регистрирует клиента и не получает токен; ваш сеанс Claude он не проверяет.
